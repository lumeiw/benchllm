# ИС ОЗЯМ-ФОП · часть 2 · Граф

Граф школьной программы в духе K12-KGraph, но с обратным порядком работы. K12-KGraph извлекает граф из учебников, и знание лежит прямо в узлах. У нас каркас — официальная программа (приказ), а знаний в ней нет. Поэтому граф здесь — **карта**: что знать, в каком классе, в каком объёме, на что опирается и где проверяется. Наполнять узлы знаниями будет часть 3.

## Слои

| Слой | Папка | Откуда | Статус |
|---|---|---|---|
| Каркас | `каркас/` | разметка приказа (часть 1) | вся история и физика |
| Понятия | `понятия/` | извлечение из текстов элементов и пунктов ОГЭ/ЕГЭ; у каждого понятия — цитата-основание из приказа | пилот: история 5 кл., физика 7–8 кл., пункты ОГЭ к ним |
| Связи между понятиями | `связи/` | экспертная разметка (LLM по инструкции, автоматическая проверка) | пилот: те же классы |
| Весь граф | `граф/` | сборка слоёв | — |

## Узлы

| type | что это | сколько |
|---|---|---|
| `subject`, `grade`, `exam` | предмет, класс, экзамен (ОГЭ/ЕГЭ по предмету) | 2 / 12 / 4 |
| `section`, `element` | раздел и элемент содержания кодификатора по классам; у элемента — часы и доля времени класса | 89 / 627 |
| `requirement_group`, `requirement` | группа умений и умение (проверяемое требование) класса | 62 / 410 |
| `lesson` | урок: история — из приказа, физика — из Конструктора edsoo (базовый) | 867 |
| `exam_section`, `exam_element`, `exam_requirement` | раздел, пункт и требование кодификатора ОГЭ/ЕГЭ; у пунктов физики — `text_latex` с формулами | 35 / 301 / 53 |
| `concept` | понятие: `label`, `ctype` (тип), `grades`, `first_element`, `aliases`, `formulas`, `dates`, `exam_items` | 678 (пилот) |

Типы понятий. История: событие, процесс, личность, государство_народ, место, документ, термин, памятник_культуры, религия_верование, период. Физика: явление, величина, закон, модель, понятие, опыт, прибор, природное_явление.

| type | откуда → куда | смысл | аналог в K12-KGraph |

| `is_part_of` | элемент → раздел → класс → предмет и т. д. | структура документа | is_part_of |

| `reviewed_in` | элемент/раздел → урок повторения | повторение | — |

`order_issue: true` — предпосылка по смыслу нужна, а в программе появляется позже. Это кандидаты на проверку, а не доказанные ошибки программы.

## Пилот: что получилось

- **Понятия.** 112 элементов и 61 пункт ОГЭ → 678 понятий, 903 упоминания. История 5 кл. — 296 понятий (в среднем 11 на элемент, Древний Египет — 37). Физика 7–8 кл. — 392 понятия (с пунктами ОГЭ). У 37 понятий физики есть формулы из кодификатора ОГЭ (MinerU). Все цитаты-основания автоматически сверены с текстом приказа.
- **Связи.** 865 связей, у каждого понятия пилота есть хотя бы одна. Физика 7–8: 302 «нужно знать до», 89 «вид», 61 «опыт подтверждает», 16 «часть». История 5: 155 «нужно знать до», 177 «часть», 39 «участник», 26 «вид». Циклов нет.
- **Глубина цепочек «нужно знать до».** Физика — до 14 шагов: «Конструирование ареометра» опирается на цепочку от «вещества» и «массы» через плотность, давление и закон Архимеда. История — до 6 шагов: это скорее «сеть контекста», чем лестница.
- **Порядок в программе (18 кандидатов).**
  - Содержательных — 5: «Объём» появляется после «Плотности» (7 кл. 4.2 и 3.4); «Атмосферное давление» — после «Давления жидкости», хотя формула p = p₀ + ρgh его уже содержит; «Закон сохранения энергии» — после «Уравнения теплового баланса» (8 кл.); «Постоянный магнит» — после «Магнитного действия тока»; «Скорость» — после связи «температура ↔ скорость частиц».
  - 10 — особенность формата кодификатора: прибор описан в последней строке раздела «Технические устройства», а практическая работа с ним стоит раньше.
  - В истории — 3, например «Цивилизация» вводится раньше «Письменности», которая входит в её определение.
- **Оговорки.** Связи — экспертная разметка LLM по инструкции. Они проверены автоматически (id, типы, циклы, порядок) и выборочно вычитаны, но не предметником. В истории «нужно знать до» местами смешивает предпосылку и причину. Если для бенчмарка это важно, можно выделить отдельный тип «ведёт к» (как leads_to в K12).

## Как собрать

```
python3 build_skeleton.py            # каркас/ из ../1_разметка
python3 понятия/build_concepts.py    # понятия/concepts.jsonl, mentions.jsonl из понятия/*/out_*.json + синонимы.json
python3 build_graph.py               # граф/ = каркас + понятия + связи/*/out_*.json
python3 просмотр/build_viewer.py     # просмотр/index.html
```

Новые классы добавляются так же, как пилот:
1. Положить `in_*.json` в новую подпапку `понятия/`.
2. Извлечь понятия по `понятия/ИНСТРУКЦИЯ_извлечение.md` и проверить `понятия/check_concepts.py`.
3. Собрать понятия.
4. Проставить связи по `связи/ИНСТРУКЦИЯ_связи.md` и проверить `связи/check_relations.py`.
5. Собрать граф.

## Посмотреть кодом

`python3 примеры.py` — загрузка графа стандартной библиотекой Python и готовые запросы: карточка понятия, цепочка «что нужно знать до», понятия элемента, связи с пометкой «порядок». `python3 примеры.py "плотность"` — карточка одного понятия. Если установлен networkx, скрипт дополнительно ищет самую длинную цепочку предпосылок.

## Gephi / yEd / Neo4j

- `граф/понятия.graphml` — только понятия и связи между ними (678 узлов, 865 связей): лучший файл для Gephi.
- `граф/graph.graphml` — весь граф (3 140 узлов). В обоих файлах тип узла лежит в атрибуте `kind`, тип связи — в `relation`, потому что «Type» в Gephi — служебная колонка.
- `nodes.jsonl` и `edges.jsonl` загружаются в Neo4j через `apoc.load.json` или в любую базу (в PostgreSQL — две таблицы с jsonb).
