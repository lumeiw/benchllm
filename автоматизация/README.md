# ИС ОЗЯМ-ФОП · автоматизация

Два конвейера, каждый запускается одной командой:

- **разметка и граф** (части 1–2): на вход — PDF приказа (и при желании выгрузки Конструктора и MinerU), на выход — та же разметка и тот же граф, что лежат в `1_разметка/` и `2_граф/`;
- **бенчмарк по срезу** (части 3–4): на вход — граф и выгрузка уроков «Библиотеки ЦОК» для одного предмета и класса, на выход — знания с цитатами и полный набор заданий, как в `3_знания/физика_7/` и `4_бенчмарк/физика_7/`. Описание — в разделе [Бенчмарк](#бенчмарк-знания-и-задания-по-срезу).

Все шаги, где раньше нужно было суждение (эксперт или Claude в чате), выполняет **LLM**. Её подключают по адресу сервера, поэтому подойдёт локальная Qwen или любая другая модель. Каждый ответ модели проверяется программой; ответ с ошибками возвращается модели на исправление.

Папка самостоятельная: остальные папки проекта она не меняет. Данные проекта читаются только в режиме `replay` (проверка воспроизводимости) и как пути к исходным файлам в конфиге (PDF, граф, выгрузка ЦОК).

## Быстрый старт

```bash
cd автоматизация
pip install -r requirements.txt            # + pdftotext (poppler-utils): brew install poppler / apt install poppler-utils

# 1) проверка: собрать всё заново из PDF, вместо модели взять прошлые решения → должно совпасть с проектом
python3 run.py конфиги/проект_2024.json --llm replay
python3 сравнить.py прогоны/проект_2024 ..          # ожидается «совпало файлов: 20 из 20»

# 2) настоящий прогон с моделью (адрес и имя модели — в конфиге, раздел "llm")
python3 run.py конфиги/проект_2024.json --run qwen
python3 оценка.py прогоны/qwen прогоны/проект_2024  # насколько модель совпала с пилотом
```

Остальные команды:

```bash
python3 run.py конфиги/проект_2024.json --list                     # этапы
python3 run.py конфиги/проект_2024.json --run qwen --from понятия_llm   # продолжить с этапа
python3 run.py конфиги/проект_2024.json --run qwen --only связи_llm     # только один этап
python3 run.py конфиги/проект_2024.json --run ручной --llm manual       # запросы к модели файлами
```

## Подключение модели

Нужен сервер с OpenAI-совместимым API (`/v1/chat/completions`):

- **vLLM / SGLang** — для больших моделей на GPU-сервере: `адрес` = `http://<сервер>:8000/v1`;
- **llama.cpp** (`llama-server`) — адрес `http://<сервер>:8080/v1`;
- **Ollama** — адрес `http://localhost:11434/v1`;
- **LM Studio** — адрес `http://localhost:1234/v1`.

Раздел `llm` в конфиге:

| ключ | что задаёт |
|---|---|
| `режим` | `api` — модель по адресу; `manual` — запросы файлами; `replay` — прошлые решения |
| `адрес`, `модель` | сервер и имя модели, как его знает сервер |
| `ключ_из_переменной` | имя переменной окружения с ключом, если сервер его требует |
| `температура` | 0 — воспроизводимые ответы |
| `макс_токенов` | предел длины ответа; для понятий истории нужно до ~4 тыс. токенов на запрос |
| `json_режим` | просить у сервера строгий JSON (`response_format`); выключите, если сервер его не поддерживает |
| `доп_параметры` | что добавить в тело запроса как есть. Для Qwen3 без режима рассуждений: `{"chat_template_kwargs": {"enable_thinking": false}}` |
| `параллельно` | сколько запросов одновременно (vLLM хорошо обрабатывает 4–16) |
| `повторов` | сколько раз вернуть ответ на исправление, если проверка нашла ошибки |
| `кэш` | папка кэша ответов: повторный прогон спрашивает модель только о том, что изменилось |
| `*_за_запрос`, `каталог_целиком_до`, `кандидатов_на_понятие` | размер одного запроса (см. ниже) |

Размер запросов на пилоте: вход до ~16 тыс. токенов (связи), обычно 4–10 тыс.; выход до ~4 тыс. Окна контекста в 32 тыс. хватает с запасом.

Ответы `<think>…</think>` и JSON в ```-оградах разбираются автоматически.

Как устроены шаги с LLM:

- **Привязки (уроки, экзамен, умения).** Сначала алгоритм делает привязку сам. Модель получает его предложение и список вариантов и подтверждает или исправляет. В `решения/*.json` попадают только исправления — в том же формате, что старые ручные правки (`overrides.json` и др.). Рядом лежит `*.подробно.json`: что предлагал алгоритм и что выбрала модель.
- **Понятия.** Модель получает по 6 элементов. Цитата-основание (`evidence`) у каждого понятия проверяется как точная подстрока текста приказа.
- **Синонимы.** Модель получает все имена понятий одного предмета и типа и объединяет одинаковые.
- **Связи.** Каждое понятие по очереди становится «опорным». Для него модель ставит его предпосылки и связи «вид / часть / участник / подтверждает» к другим понятиям. Так каждая связь решается один раз, а запрос не растёт с размером программы: если понятий больше `каталог_целиком_до`, в каталог идут только кандидаты. Циклы, дубли и пометку `order_issue` (предпосылка появляется в программе позже) делает программа, а не модель.

Все промпты лежат в `промпты/*.md`, их можно править без изменения кода. Комментарии `<!-- -->` в промпт не попадают.

## Режимы LLM

- **api** — обычный прогон с моделью.
- **manual** — запросы пишутся в `прогоны/<имя>/llm/запросы/<этап>/*.md`. Ответ (только JSON) нужно положить в `llm/ответы/<этап>/` с тем же именем и запустить этап снова: `run.py … --from <этап>`. Так можно отвечать любой моделью через чат или проверить промпт руками.
- **replay** — вместо модели берутся прошлые решения проекта (пути — в разделе `replay` конфига). Нужен для проверки, что пайплайн воспроизводит текущие данные. Прогон занимает около минуты.

## Новый документ (другая редакция ФОП)

1. Скопируйте `конфиги/проект_2024.json`, например в `конфиги/фоп_2025.json`.
2. Укажите новый `источник.pdf`, `редакцию` и имя `прогон`.
3. При необходимости поправьте `понятия.наборы` и `связи.наборы` (какие классы размечать).
4. Если для физики есть свежие выгрузки Конструктора — пропишите их в `физика_конструктор`. Формулы MinerU (`mineru`) необязательны.
5. Запустите: `python3 run.py конфиги/фоп_2025.json`.
6. Сравните с прошлой редакцией: `python3 сравнить.py прогоны/проект_2024 прогоны/фоп_2025 --записи` — какие элементы, умения и уроки добавлены, убраны, изменены.

Ограничение: разбор PDF (`этапы/разметка/fop_markup.py`) написан под вёрстку проекта приказа 2024 года. На документе с другой вёрсткой (например, выгрузка из Гаранта) его, вероятно, придётся доработать. Следующий шаг — отдельный разборщик под каждый формат источника с одним общим форматом на выходе.

## Бенчмарк: знания и задания по срезу

Конфиг с `"вид": "бенчмарк"` (`конфиги/физика_7.json`, `конфиги/физика_8.json`, `конфиги/физика_9.json`, `конфиги/физика_10.json`, `конфиги/физика_11.json`) запускает части 3–4 для одного среза графа — предмета и класса. Этапу `цепочки` нужен пакет `sympy` (`pip install sympy`).

```bash
python3 run.py конфиги/физика_7.json --llm replay      # проверка: решения пилота вместо модели
python3 сравнить.py прогоны/физика_7 ..                 # ожидается «совпало файлов: 6 из 6»
python3 run.py конфиги/физика_7.json --run физика_7_qwen   # прогон с моделью
python3 run.py конфиги/физика_8.json --run физика_8_replay --llm replay   # 8 класс: части 3–4 из решений manual-прогона
python3 сравнить.py прогоны/физика_8_replay ..          # ожидается «совпало файлов: 6 из 6»
python3 run.py конфиги/физика_9.json --run физика_9_replay --llm replay   # 9 класс — так же
python3 сравнить.py прогоны/физика_9_replay ..          # ожидается «совпало файлов: 6 из 6»
python3 run.py конфиги/физика_10.json --run физика_10_replay --llm replay # 10 класс — так же
python3 сравнить.py прогоны/физика_10_replay ..         # ожидается «совпало файлов: 6 из 6»
python3 run.py конфиги/физика_11.json --run физика_11_replay --llm replay # 11 класс — так же
python3 сравнить.py прогоны/физика_11_replay ..         # ожидается «совпало файлов: 6 из 6»
```

| № | этап | кто | что делает | результат |
|---|---|---|---|---|
| 1 | `срез` | программа | понятия, элементы, умения и связи класса из графа; вес понятия по часам | `3_знания/<срез>/срез.json` |
| 2 | `цок_корпус` | программа | выгрузка ЦОК → текстовые единицы (тесты с ключами, страницы, интерактивы, субтитры) с уроком и ссылкой | `источники/цок_корпус.jsonl` |
| 3 | `знания_кандидаты` | программа | для каждого понятия — до 25 подходящих предложений корпуса (по основам слов и `поиск_синонимы.json`) | `кандидаты.json` |
| 4 | `знания_llm` | **LLM** | по 4 понятия: знания уровня класса, у каждого — цитаты, точные подстроки кандидатов, элемента ФОП или пункта ОГЭ | `решения/знания.json` |
| 5 | `знания` | программа | повторная проверка цитат, статусы, id знаний | `знания.jsonl` |
| 6 | `формулы_llm` | **LLM** | формулы класса в школьной форме, обозначения, единицы; для формул сложного вида — три неверные записи | `формулы.json` |
| 7 | `задания_llm` | **LLM** | по разделам: типичные ошибки, ситуации «что за явление», вопросы «почему», неверные формулировки законов, прочие задания | `решения/задания_llm.json` |
| 7а | `цепочки_роли_llm` | **LLM** | для каждой буквы формулы: к какому объекту относится величина (ρ тела ≠ ρ жидкости), как назвать в условии, правдоподобные значения; условие применимости формулы | `решения/цепочки_роли.json` |
| 7б | `цепочки` | программа | кандидаты многошаговых расчётных задач: формулы среза сцепляются по общей величине, глубина — ровно по норме своего класса (умение «решать…»: 7 кл. «1–2 действия» → 2, 8 кл. «2–3» → 2–3, 9 кл. «2–3 уравнения» → 2–3; нет числа, как в 10 кл. «с явно заданной физической моделью», — 2–3), глубже нормы не строится. Формулы прошлых классов подключаются ключом конфига `формулы_прошлых_классов`, но в каждой цепочке есть формула текущего класса. | `4_бенчмарк/<срез>/цепочки_кандидаты.md` |
| 7в | `цепочки_llm` | **LLM** | проверяющий решает по каждому набору формул «ок/нет»: одна ли это ситуация, естественна ли задача для класса; в задания (C2) идут только «ок» | `решения/цепочки.json` |
| 8 | `задания` | программа | 31 семейство заданий из графа, знаний, формул, материала LLM, шаблонов расчёта и одобренных цепочек (C2) | `4_бенчмарк/<срез>/задания.jsonl` |
| 9 | `дистракторы_llm` | **LLM** | проверяющий ищет тестовые задания, где неверный вариант можно защитить как верный или неверен ключ | `решения/дистракторы.json` |
| 10 | `итог` | программа | пометка «варианты под вопросом», `сводка.json`, `задания.md`, `просмотр.html`, автоматическая проверка набора | `4_бенчмарк/<срез>/` |

**Как получаются правильные и неверные ответы.** Правильный ответ берётся из ребра графа, знания с цитатой, формулы или расчёта по шаблону. Неверные варианты подбирает программа: это понятия, не связанные с ответом ни ребром, ни родом или видом, ни частью, ни общей формулой, ни похожим названием, ни ручной «близкой парой». В заданиях «что нужно знать до» неверные варианты — понятия, которые сами опираются на данное: в графе без циклов они не могут быть его предпосылками. Неверные варианты, которые пишет модель (ситуации, формулировки законов, ошибки учеников), проверяет программа: они должны быть из списка понятий и не быть родом, видом или частью ответа. Затем все тестовые задания ещё раз просматривает модель-проверяющий (этап 9).

**Умения ФОП по ролям.** Номера умений в 7 и 8 классах разные (например, «приводить примеры» — 1.15 в 7 классе и 1.16 в 8). Поэтому семейства заданий, промпты и шаблоны ссылаются на роль умения (`понятия`, `различать`, `решать`, `прямые`, `приборы`, `примеры`…), а код подбирается у класса по тексту умения (`ROLES` в `этапы/бенчмарк/bench_common.py`). Если у класса нет умения с такой ролью, сборка сообщит об этом в `сводка.json → проблемы_сборки`. Для 9 класса добавлены две роли: `модели` — 9 кл. 1.14 «различать основные признаки изученных физических моделей» и `схемы` — 8 кл. 1.15 «распознавать простые технические устройства… по схемам» и 9 кл. 1.16 «использовать схемы и схематичные рисунки…».

**Умения СОО (10 класс).** Формулировки умений ФОП среднего общего образования другие, поэтому у ролей есть вторые варианты текста (`ROLES`): например, `решать` — 10.13 «решать расчётные задачи с явно заданной физической моделью», `прямые` и `косвенные` — 10.10 «осуществлять прямые и косвенные измерения», `исследование` — 10.11 «исследовать зависимости», `модели` — 10.2 «учитывать границы применения моделей». Добавлены роли `учёные` (10.16 «приводить примеры вклада учёных») и `картина` (10.1 «роль физики в научной картине мира»). Умения «использовать понятия» в 10 классе нет, а «описывать» разделено на три умения по разделам. Для таких ролей код берётся по разделу главного понятия задания из `ручные_данные/<срез>/умения.json` (`{"понятия": {"2": "10.4", …}, "описывать": {…}}`). В 11 классе добавлены роли `направление` (11.7 «определять направление вектора индукции, силы Ампера и силы Лоренца») и `изображение` (11.8 «строить и описывать изображение в плоском зеркале и тонкой линзе»); в 7–10 классе таких умений нет, и реплей этих классов не меняется.

**Формулы прошлых классов.** Справочник формул среза объединяется с формулами из `формулы_прошлых_классов`: сначала формулы текущего класса, затем прошлые классы в порядке списка. Если формула с тем же id уже есть, следующая копия не берётся. Так F.power, которая есть и в 7, и в 8 классе, в цепочки 9 класса попадает один раз — из 7 класса. Если текущий класс записывает формулу прошлого класса заново под тем же id (в 10 классе — F.current, F.resistance, F.force_impulse и ещё 5), берётся запись текущего класса. Но запись класса из середины списка проигрывает более ранним: в 11 классе F.potential, F.engine_efficiency и F.force_impulse берутся в версии 7–9 класса, а не 10.

**Константы и пределы цепочек.** В `справочные_данные.json` среза можно задать два необязательных ключа, которые читает движок цепочек (`этапы/бенчмарк/chains_engine.py`):
- `константы_цепочек` — `{понятие: число}`: величины, которые в задаче не вычисляются, а даются в условии («Примите R = 8,31 Дж/(моль·К)»). Кроме g, в 10 классе это универсальная газовая постоянная и коэффициент закона Кулона, в 11 классе — ещё скорость света и расстояние наилучшего зрения;
- `пределы_цепочек` — `{понятие: [мин, макс]}`: физические пределы вычисленной величины. Если она выходит за предел, движок подбирает другие числа. В 10 классе: молярная масса, влажность не больше 100 %, КПД тепловой машины меньше 1; в 11 классе добавлены КПД трансформатора, показатель преломления и скорость света в среде.

Без этих ключей движок работает как раньше (7–9 класс).

**id заданий G1.** Ключ задания «вид понятия» — слаг понятия. Если у понятия в срезе несколько родов, к нему добавляется слаг рода (`G1.<понятие>.<род>`), чтобы id не повторялись.

**Сборка детерминирована.** Варианты перемешиваются с зерном от id задания; id не зависят от порядка обхода. Повторный прогон с теми же решениями даёт тот же файл байт в байт.

### Новый класс (на примере 8 класса физики)

1. **Выгрузить уроки ЦОК.** Войти на academy-content.apkpro.ru, открыть каталог `https://academy-content.apkpro.ru/ru/catalog/03/08?class=08`, в консоли браузера (F12 → Console) вставить `этапы/бенчмарк/цок_выгрузка.js` целиком. Через несколько минут скачается `цок_03_08.json`. Положить его в `3_знания/физика_8/источники/` (путь — ключ `цок` конфига).
2. **Конфиг** — по образцу `конфиги/физика_8.json`: срез, путь к выгрузке, адрес модели. У нового класса раздел `replay` пустой — прошлых решений нет; в 8 классе он теперь ведёт на решения, составленные в режиме `--llm manual` (`3_знания/физика_8/решения/`, `4_бенчмарк/физика_8/решения/`). Для 10–11 класса в срезе указывается `"уровень": "SOO"`: понятия, умения и пункты кодификатора берутся из среднего общего образования (ЕГЭ), а цитата из кодификатора в ответе модели (источник «ОГЭ» с кодом пункта) может вести и на пункт ЕГЭ, и на пункт ОГЭ, связанный с понятием.
3. **Ручные данные** `ручные_данные/физика_8/` — необязательны, без них конвейер работает:
   - `доп_понятия.json` — понятия, которые есть только в пунктах ОГЭ, но относятся к темам класса (`[{"метка", "элемент", "основание"}]`);
   - `близкие_пары.json` — пары понятий, которые нельзя ставить неверным вариантом друг к другу;
   - `близкие_формулы.json` — пары id формул (`[["F.planck", "F.work_function"], …]`): в заданиях F1 правая часть одной формулы не даётся неверным вариантом к другой. Нужен, когда чужая запись с левой частью задания остаётся верной (p = E/c для импульса фотона). Если такой пары нет, неверный вариант выбирается как раньше, поэтому файл не меняет задания других срезов;
   - `поиск_синонимы.json` — дополнительные слова для поиска кандидатов в корпусе;
   - `цепочки.json` — обычно не нужен: роли величин и отбор наборов делает модель (этапы `цепочки_роли_llm`, `цепочки_llm`). Его `роли`, `условия`, `значения`, `решения` применяются поверх решений модели. В 8 классе файл нужен: буквы формул совпадают с 7 классом (ρ, E, P, R, A, t), и программа без подсказки берёт для них понятие и единицу 7 класса; здесь они заданы явно. В 9 классе совпадений больше (p, λ, c, R, A, N, M, h, x, v с 7 и 8 классом), поэтому роли заданы для всех 52 формул, которые идут в цепочки. В 10 классе буквы совпадают и внутри класса (U — напряжение и внутренняя энергия, R — сопротивление и газовая постоянная, k — три разные константы), поэтому понятие и единица заданы для 107 формул: у формул 7–9 класса — как в сборке 9 класса, у формул 10 класса — по смыслу.
   - `справочные_данные.json` и `шаблоны_расчёт.py` — для расчётных и измерительных заданий (C, M, I, R). Шаблон — функция на Python, которая по зерну выбирает числа и считает ответ. Без этого файла задания с расчётом не строятся. Пример — `ручные_данные/физика_7/`.
4. **Запуск:** `python3 run.py конфиги/физика_8.json --run физика_8_qwen`. Если модель недоступна, можно ответить на запросы самому через чат: `--llm manual`.
5. **Вычитка:** в `просмотр.html` отфильтровать статусы «LLM, на вычитку» и «варианты под вопросом»; в `знания.jsonl` — статус «без источника».

Размер запросов на 7 классе: самый большой запрос — около 35 тыс. символов (знания: 4 понятия с кандидатами), самый большой ответ — около 17 тыс. символов (задания одного раздела). Это примерно 12 тыс. и 6 тыс. токенов; окна контекста в 32 тыс. хватает. Всего запросов: знания — 38, формулы — 1, задания — 5, проверка вариантов — 33. На 8 классе: знания — 43, формулы — 1, задания — 2, роли величин — 1, наборы цепочек — 26, проверка вариантов — 45. На 9 классе: знания — 51, формулы — 1, задания — 5, роли величин — 1, наборы цепочек — 45, проверка вариантов — 55. Самый большой запрос 9 класса — задания раздела «Механические явления», около 50 тыс. символов (68 понятий со знаниями), ответ к нему — около 26 тыс. Запрос ролей величин — около 40 тыс. символов, ответ — около 50 тыс. (77 формул). Это примерно 14 тыс. и 17 тыс. токенов, поэтому ответ уже не помещается в `макс_токенов` = 16384, а вместе с запросом — в окно 32 тыс. Для 9 класса нужно окно больше или деление этого запроса на части. На 10 классе: знания — 41, формулы — 1, задания — 9 (по одному на подраздел), роли величин — 1, наборы цепочек — 71, проверка вариантов — 46. Самый большой запрос знаний — около 39 тыс. символов, заданий — около 40 тыс. (подраздел 4.2), ролей величин — около 68 тыс. (132 формулы), ответ к нему — около 85 тыс. символов (примерно 25–28 тыс. токенов). Для этого запроса нужно окно не меньше 64 тыс. токенов и `макс_токенов` не меньше 32 тыс., либо деление на части. На 11 классе: знания — 56, формулы — 1, задания — 9, роли величин — 1, наборы цепочек — 20, проверка вариантов — 61. Самый большой запрос заданий — около 64 тыс. символов (раздел 8 «Астрофизика», 48 понятий), знаний — около 39 тыс., ролей величин — около 86 тыс. (172 формулы), ответ к нему — около 111 тыс. символов с отступами. Требования к окну те же, что в 10 классе.

Ограничения:
- Скрипт выгрузки ЦОК опирается на текущую вёрстку и адреса сайта; если сайт изменится, его придётся поправить. Картинки-конспекты не выгружаются, поэтому часть знаний остаётся «без источника».
- Шаблоны расчёта (C, M, I, R) пишутся руками для каждого класса. Многошаговые задачи (C2) строятся без ручных действий: перебор и числа — программа, роли величин и отбор осмысленных наборов — модель. На пилоте (7 класс), в 8, 9, 10 и 11 классе решения модели составил Claude, они подключены как replay. Качественные задачи «цепочкой рассуждений» (умение 10.14) цепочками формул не покрываются: для них есть K7 «объяснить явление». В 10 классе формулы постоянного тока сцепляются гораздо чаще остальных, поэтому 665 из 847 задач C2 — на замкнутую цепь (см. `4_бенчмарк/физика_10/README.md`). В 11 классе так же 171 из 294 задач C2 — сила Ампера вместе с формулами постоянного тока.
- Движок цепочек записывает числа условия без множителя 10ⁿ: значение меньше 10⁻⁹ он запишет как «0». Поэтому формулы микромира и астрофизики 11 класса (энергия фотона, де Бройль, энергия связи, закон Хаббла) в цепочки не включены. Их проверяют шаблоны C с ответом в долях единиц (эВ, нм, 10⁻¹⁹ Дж). Буква ℰ (ЭДС индукции) движком не разбирается.
- Конвейер проверен на физике. Для истории формулы и расчёт пропускаются, но промпты и семейства заданий под историю не настраивались.

## Ручные данные

`ручные_данные/<документ>/` — то, что пока задаётся руками для разметки и графа:

- `exam_extra.json` — связи элементов 7–9 кл. с ЕГЭ;
- `deep_fill.json` и `deep_lessons.json` — какие элементы физики без уроков в базовом плане берут часы из углублённого.

Без этих файлов пайплайн работает: физика считается только по базовому плану, а дополнительных связей с ЕГЭ нет.

`ручные_данные/физика_7/`, `ручные_данные/физика_8/`, `ручные_данные/физика_9/`, `ручные_данные/физика_10/`, `ручные_данные/физика_11/` — данные бенчмарка 7–11 класса (состав описан в разделе «Новый класс»; справочные данные 8 и 9 класса — по демоверсии ОГЭ 2026, 10 и 11 класса — по таблице «Справочные данные» КИМ ЕГЭ; в 10 классе добавился `умения.json`).

## Ориентир для оценки модели

Если модель всегда соглашается с алгоритмом, с пилотом (решения эксперта и Claude) совпадает:

- уроки истории — 78%;
- уроки физики — 78%;
- связь с экзаменом — 76%;
- умения — 92%.

Это нижняя планка: чтобы этап с LLM имел смысл, модель должна поднимать эти цифры. `оценка.py` считает их для любого прогона.
